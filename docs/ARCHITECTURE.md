# معماری اپلیکیشن وِفاق (Wefagh)

## ۱. اهداف
- اپ رسمی گروه وکلای مدافع فرهنگ، اندیشه و قانون «وفاق» روی **wefagh.ir** با HTTPS.
- فارسی و راست‌چین، تاریخ شمسی، هویت بصری کرم / بژ / قهوه‌ای.
- بخش‌های: معرفی، آکادمی مجازی، محاسبه‌گرهای حقوقی، رسانه و پادکست، عضویت، بانک قوانین، مشارکت صنفی، پنل مدیریت، و زیرساخت آمادهٔ دستیار هوشمند.

## ۲. تصمیم‌های فنی و دلیل آن‌ها

| حوزه | انتخاب فاز ۱ | دلیل | مسیر ارتقا |
|---|---|---|---|
| رابط کاربری | HTML/CSS/ES Modules خالص | بدون build، بدون وابستگی، قابل تست با Node | در صورت رشد، مهاجرت به React/Vite (فاز بعد) |
| API | Cloudflare Worker (Web Standard `fetch`) | همان محیط اجرای Cloudflare، بدون وابستگی | افزودن Hono وقتی registry در دسترس باشد |
| پایگاه داده | Cloudflare D1 (SQLite) | یکپارچه با Cloudflare، ساده برای داده‌های رابطه‌ای | — |
| فایل‌ها (صوت پادکست، PDF قوانین) | Cloudflare R2 | بدون هزینهٔ egress | — |
| احراز هویت | ایمیل + رمز عبور (PBKDF2 با Web Crypto) + کوکی HttpOnly | بدون سرویس خارجی | OTP ایمیلی یا ورود با Google در فاز بعد |
| ضد اسپم فرم‌ها | Cloudflare Turnstile | رایگان و بدون اصطکاک | — |
| تاریخ شمسی | `Intl` با `fa-IR-u-ca-persian` | بدون کتابخانه؛ تست‌شده در Node 22 | — |
| فونت | وزیرمتن (Vazirmatn) | فارسی، متن‌باز | میزبانی محلی به‌جای CDN خارجی |

## ۳. نمودار کلی

```
کاربر ──HTTPS──► Cloudflare (wefagh.ir)
                  ├─ /            → Cloudflare Pages   (site/, استاتیک)
                  └─ /api/*       → Worker             (worker/src/index.js)
                                      ├─ D1  (کاربران، جلسات، پیام‌های تماس، آکادمی، قوانین …)
                                      ├─ R2  (فایل‌های صوتی و PDF)
                                      └─ Turnstile (تأیید فرم‌ها)
```

Pages و Worker روی یک زون (`wefagh.ir`) با قانون مسیر (Route) به‌هم وصل می‌شوند، پس مرورگر فقط با یک دامنه و یک گواهی HTTPS کار می‌کند و کوکی‌ها هم‌مبدأ (same-origin) هستند.

## ۵. مدل داده (فاز ۱ و آماده برای فازهای بعد)
- `contact_messages` — پیام‌های فرم تماس (فاز ۱، پیاده‌سازی شده).
- `users`, `sessions` — عضویت و نشست (فاز ۵، طرح آماده).
- `courses`, `enrollments`, `lessons` — آکادمی (فاز ۳).
- `articles`, `episodes` — رسانه و پادکست (فاز ۴).
- `laws`, `judgments` — بانک قوانین و رویه قضایی (فاز ۶).
- `cooperative_requests` — سامانه مشارکت صنفی (فاز ۷).
- `admin_roles` — نقش‌های مدیریتی (فاز ۸).

## ۶. امنیت
- رمزهای عبور فقط به‌صورت هش PBKDF2 (SHA-256، ۱۰۰٬۰۰۰ تکرار، نمک تصادفی) ذخیره می‌شوند.
- کوکی نشست: `HttpOnly; Secure; SameSite=Lax`.
- تمام ورودی‌ها در Worker اعتبارسنجی و طول‌بندی می‌شوند؛ خروجی HTML در فرانت‌اند escape می‌شود (هرگز `innerHTML` با داده کاربر).
- هدرهای امنیتی (CSP، HSTS، X-Content-Type-Options) در `_headers` ابتدای استقرار Pages.
- محدودیت نرخ (Rate limit) فرم‌ها با Turnstile و در فاز بعد با Durable Object.

## ۷. وضعیت پیاده‌سازی
این بخش فقط وضعیت واقعی را ثبت می‌کند. هر قابلیت پس از تست در اینجا به «آزموده‌شده» تغییر می‌کند.

| قابلیت | وضعیت |
|---|---|
| معماری و ساختار پوشه‌ها | ✅ ایجاد شد |
| تاریخ شمسی (Intl) | ✅ آزموده‌شده با Node 22 |
| اعتبارسنجی فرم تماس | ✅ تست واحد دارد (اجرا در Node) |
| API تماس + ذخیره در D1 | ⚠️ با fake env آزموده شد؛ D1 واقعی هنوز آزموده نشده |
| صفحات معرفی و ناوبری | ⚠️ ساخته شد؛ تست مرورگری انجام نشده |
| استقرار روی Cloudflare | ❌ انجام نشده (نیاز به حساب و دسترسی شبکه) |
| آکادمی، محاسبه‌گرها، رسانه، عضویت، قوانین، مشارکت، پنل | ❌ در فازهای بعد |
