# گزارش بررسی اولیه آکادمی وفاق

تاریخ بررسی: ۲۰۲۶-۱۰-۲۸
منبع: بستهٔ ZIP تحویلی با ریشهٔ `Wefagh-main/`؛ این بسته تاریخچهٔ Git ندارد.

## معماری مشاهده‌شده

- رابط کاربری: HTML/CSS/ES Modules خالص در `site/`، با مسیرهای hash.
- API: Cloudflare Worker در `worker/src/index.js`.
- پایگاه دادهٔ هدف: Cloudflare D1/SQLite؛ مهاجرت‌ها در `worker/migrations/`.
- استقرار هدف: Cloudflare Pages و Worker؛ تنظیم route برای `wefagh.ir/api/*` در `worker/wrangler.toml`.
- احراز هویت: ایمیل/رمز، PBKDF2، کوکی نشست HttpOnly و توکن تأیید ایمیل.
- آزمون: `node:test` و `node:sqlite`، بدون وابستگی خارجی نصب‌شونده.

## آزمون‌ها

- محیط آزمون: Node.js v22.16.0.
- ابتدا `npm run verify` اجرا شد و ۲۱ تست به علت تفاوت نحو پارامترهای شماره‌دار D1 با bind در `node:sqlite` شکست خوردند.
- آداپتورهای تست یکپارچه تغییر داده شدند تا پارامترهای `?1`, `?2`, ... را برای SQLite داخلی Node به پارامترهای ناشناس تبدیل کنند؛ کد عملیاتی Worker تغییر نکرد.
- پس از اصلاح آداپتور: ۱۳۳ تست موفق بود. در مرحلهٔ بعد بانک پرونده و API ذخیرهٔ تمرین اضافه شد؛ اجرای نهایی `npm run verify`: ۱۳۶ تست موفق، صفر شکست.
- این آزمون‌ها از D1 راه‌دور، ایمیل واقعی، میکروفون در مرورگر واقعی یا استقرار Cloudflare استفاده نمی‌کنند.

## تغییرات مرحلهٔ دوم

- ۵ پروندهٔ آموزشی کاملاً فرضی با شرح وقایع، مسائل و فهرست مدارک بالقوه افزوده شد.
- صفحهٔ فارسی بانک پرونده‌ها در مسیر `#/cases` و جزئیات در `#/cases/:id` اضافه شد.
- API فهرست/جزئیات پرونده‌ها عمومی و فقط‌خواندنی است.
- API نشست‌های موت‌کورت امکان ایجاد، فهرست، خواندن، ویرایش و حذف تمرین را فراهم می‌کند؛ دسترسی به نشست‌ها نیازمند ورود است و همهٔ عملیات به مالک محدود شده‌اند. ورودی‌ها طول‌بندی و اعتبارسنجی می‌شوند.
- رابط `site/js/moot.js` به API نشست‌ها متصل شده است: ایجاد تمرین، فهرست و بازیابی تمرین‌های ذخیره‌شده، ذخیرهٔ خودکار با تأخیر کوتاه، ذخیره هنگام خروج از فیلد و ثبت نتیجهٔ خودارزیابی. این قابلیت به ورود معتبر و اجرای مهاجرت `0005_casework.sql` در D1 نیاز دارد.
- هنوز ضبط صدا، بارگذاری صوت، داور پویا، تولید هفتگی پرونده یا پنل مدیریت محتوا پیاده‌سازی نشده‌اند.

## محدودیت‌های بررسی

- ZIP فاقد `.git`/تاریخچهٔ commit است؛ شاخه فعال، commit مبنا و تفاوت با مخزن GitHub مشخص نیست.
- دسترسی حساب Cloudflare، D1 راه‌دور، R2 و اسرار محیطی ارائه نشده است؛ هیچ استقراری انجام نشده.
- پیش از اعمال این تغییرات، نسخهٔ اصلی ZIP حفظ شده و تغییرات در پوشهٔ کاری بررسی انجام شده‌اند؛ هنوز commit یا PR به GitHub ارسال نشده است.

## تغییرات مرحلهٔ سوم

- رابط موت‌کورت به مسیرهای `/api/moot/sessions` متصل شد.
- کاربر واردشده می‌تواند تمرین ذخیره‌شونده بسازد، تمرین قبلی را انتخاب و بازیابی کند و تغییر پاسخ‌ها، چک‌لیست و مرحلهٔ جاری را ذخیره کند.
- وضعیت ذخیره‌سازی و خطاهای رایج به زبان فارسی در رابط نمایش داده می‌شود؛ کاربران بدون ورود همچنان می‌توانند تمرین کنند، اما ذخیرهٔ پایدار ندارند.
- آزمون نهایی این نسخه: ۱۳۶ موفق، صفر شکست؛ بررسی نحوی همهٔ فایل‌های JavaScript نیز موفق بود.

## تغییرات مرحلهٔ چهارم

- به مرحلهٔ «تنظیم پاسخ» در موت‌کورت، امکان ضبط دفاع شفاهی با `getUserMedia` و `MediaRecorder` اضافه شد.
- پس از پایان ضبط، فایل صوتی در پخش‌کنندهٔ داخلی قابل شنیدن و از طریق پیوند دریافت، روی دستگاه کاربر قابل ذخیره است.
- زمان ضبط حداکثر ۵ دقیقه است؛ جریان میکروفون پس از توقف ضبط آزاد می‌شود و پیام‌های مربوط به مجوز/ناسازگاری مرورگر به فارسی نمایش داده می‌شوند.
- صوت به API یا حساب کاربری بارگذاری نمی‌شود و با بارگذاری مجدد صفحه از بین می‌رود؛ این محدودیت به‌صراحت در رابط اعلام شده است.
- آزمون‌های ایستا برای حضور قابلیت ضبط، پخش، محدودیت زمانی و اطلاع‌رسانی حریم خصوصی اضافه شد.
- محدودیت آزمون: ضبط واقعی میکروفون و سازگاری دستگاه‌ها در مرورگر واقعی آزمایش نشده است؛ برای دسترسی میکروفون معمولاً HTTPS و اجازهٔ کاربر لازم است.

## مرحلهٔ پنجم — شبیه‌ساز پرسش‌گر موت‌کورت

- در رابط موت‌کورت، دو نقش پرسش‌گر آموزشی اضافه شد: قاضی و وکیل طرف مقابل.
- پرسش‌ها به پروندهٔ فرضی تأخیر در تحویل کالا متصل‌اند و می‌توان میان پرسش‌ها جابه‌جا شد.
- بازخورد پاسخ، نشانه‌های متنی مانند اشاره به واقعه/مدرک، رابطهٔ دلیل و نتیجه، درخواست روشن و ذکر شرط/نیاز به اثبات را بررسی می‌کند.
- این نسخه عمداً یک ارزیاب قاعده‌مند سمت مرورگر است؛ به مدل زبانی یا سرویس بیرونی متصل نیست و درستی حقوقی پاسخ را تأیید نمی‌کند.
- آزمون‌ها: `npm run verify` — ۱۴۱ آزمون موفق، صفر شکست.
