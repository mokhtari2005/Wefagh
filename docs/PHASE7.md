# مرحلهٔ ۷ — پنل مدیریت محتوا

## امکانات
- مسیر رابط: `#/admin`؛ پیوند از صفحهٔ حساب فقط برای نقش `admin` یا `super_admin` نمایش داده می‌شود.
- API مدیریت: `GET/POST /api/admin/content` و `PATCH/DELETE /api/admin/content/:id`.
- انواع محتوا: دورهٔ آموزشی (درس‌ها) و پروندهٔ فرضی (وقایع، مسائل و مدارک).
- وضعیت‌ها: `draft` و `published`. فقط محتوای منتشرشده در فهرست عمومی آکادمی و بانک پرونده‌ها نمایش داده می‌شود.
- حذف محتوای منتشرشده مستقیماً مجاز نیست؛ مدیر باید ابتدا آن را از انتشار خارج کند.
- تمام عملیات مدیریتی به نشست معتبر و نقش مدیر نیاز دارند. اعتبارسنجی در Worker انجام می‌شود؛ فرم مرورگر مرز امنیتی محسوب نمی‌شود.
- مهاجرت پایگاه داده: `0006_admin_content.sql`.

## قالب ورود اطلاعات
- شناسهٔ محتوا: انگلیسی کوچک، عدد و خط تیره، مانند `contract-basics`.
- درس‌های دوره: هر خط با قالب `شناسه|عنوان|متن درس`.
- وقایع و مدارک پرونده: هر خط یک مورد.
- مسائل پرونده: هر خط با قالب `شناسه|صورت مسئله`.

## نکات عملیاتی
- پیش از انتشار، محتوای آموزشی و حقوقی باید توسط مسئول علمی بررسی شود؛ انتشار به‌معنای تأیید حقوقی یا رسمی نیست.
- نقش `super_admin` از مسیر تنظیم `ADMIN_EMAIL` هنگام ثبت‌نام ایجاد می‌شود. نقش `admin` باید توسط مدیر سامانه از طریق رویهٔ امن مدیریتی به کاربر اعطا شود؛ در این فاز رابط عمومی برای اعطای نقش وجود ندارد.
- اجرای مهاجرت روی Cloudflare D1 واقعی و استقرار Pages/Worker هنوز انجام نشده است.
